# Responsive primitive skin

Generated by `scripts/deck-assets/build-responsive-primitives.py`. The manifest
contains seven primitive families and 39 statically bundled PNGs. Do not add
another full-screen A/B/C/D/E image or runtime mask over this pack.

All source references are 3 pixels per point. `referencePt` is the whole image
including its `paddingPt`; `contentRectPt` is the logical well/control inside.
For a nine-patch well, `capInsetsPt` belongs INSIDE that content rectangle.
The outer fixed image edge is padding + cap inset. Compose the nine PNGs in
manifest row/column order and stretch only middle rows/columns. This uses the
same images and arithmetic on both platforms.

LCD adaptive outer well matches `layout.status`, with `placement.outsetPt=0`.
Its 366x140 source reference is resampled to the adaptive logical target. It
does not add the original phone's nominal-LCD bezel expansion: phone has its
own unchanged full-screen skin. PTT is centered on the voice sprite rectangle
with content width 342/355 and height 354/366 of that rectangle.

Stick/dial content side is 337/3 pt, with 8 pt padding on each side. Use the
control rectangle's short side divided by 337/3 as scale, scale padding with it,
and center the square raster. Preserve aspect ratio. Metal may fill the whole
adaptive frame; its approved strip texture is intentionally permitted to scale.

RGBA outside each static primitive is pre-baked transparent; interior floors
are opaque rendered RGB. The pack never masks at runtime. Moving states,
numbers, labels and provider icons are existing sprites/native overlays.

Run the generator `--check` and `node apps/mobile/tests/responsive-assets.test.mjs`
to check hashes, real PNG/alpha/masks, nine-patch reconstruction, provenance and
the 32 unchanged phone sprites. Native routing, label fit, performance, font1.5,
rotation/fold state retention and +/-2dp screen acceptance are verified by the
app integration separately; this pack does not claim those are complete.
