# DeckSpeech

Optional Expo local module, Expo SDK 55 / RN 0.83.10. iOS deployment target 15.1; Android minSdk 24. This package does not wire itself into app dependencies or the UI. Import `DeckSpeech` from `deck-speech` after the app adds the local dependency and rebuilds its native binary.

## Contract

- `prepare(language: 'ko-KR' | 'en-US')` resolves `{ready, reason?}`. It never speaks, downloads a voice, queues text, requests a permission, or starts a service. Android initialization can return `loading`; retry preparation after initialization. There is no automatic replay.
- `speak(id, text, language, rate)` resolves `{accepted, reason?}`. Accepted means submitted to the native synthesizer, not proof of audible output. Only one utterance may be active. IDs must be nonempty and at most 128 UTF-16 code units; text must be nonempty and at most 4000 UTF-16 code units (also bounded by Android's native maximum). Rate is a finite 0.5–2.0 multiplier; iOS scales its default rate and clamps to its native min/max. Other inputs fail closed as `unavailable`.
- IDs must be unique for the module instance. A text-free, bounded ledger rejects reuse and refuses new submissions after 8192 IDs. A duplicate never emits another terminal event. Native callbacks use a private token/object identity; an old callback cannot complete another utterance.
- `stop()` resolves `true` only when no request was submitted or the exact active request received a native terminal callback. A stop return value or `isSpeaking == false` before native start does **not** establish cancellation. At one second without a callback, it resolves `false`; the canceled run remains quarantined and new speech is rejected. A later native callback still emits its single terminal event. A canceled late start is stopped again and is never announced as started.
- `dispose()` permanently disables this module instance, requests the same confirmed stop and returns its result. Teardown retains native cancellation state until a terminal callback; it does not fake completion because JS listeners were removed. A missing callback can therefore retain one quarantined native engine. No automatic recovery, retry or replay is provided.
- Events: `onSpeechStarted: {id}` and `onSpeechFinished: {id, reason: 'finished'|'stopped'|'error'|'interrupted'}`. A stop/interruption reason is latched before calling native cancellation. Repeated, old and conflicting callbacks do not emit another terminal event. OS failure to deliver a callback is uncertainty, not a synthetic terminal event.
- Preparation/submission failures use only `unavailable`, `loading`, `background`, `busy`, `focus_denied`. The TS wrapper maps missing/throwing native module calls to unavailable, and uncertain stop/dispose to `false`.

The application audio arbiter must acquire an exclusive speech lease before `speak` and retain it until confirmed native completion. It must exclude microphone capture and must not release on stop timeout, dispose timeout, listener removal, or submission uncertainty. This module does not acquire microphone permission or change the app's recording session.

## Local voice and lifecycle policy

**iOS:** enumerate `AVSpeechSynthesisVoice.speechVoices()`, require exact language, an Apple system identifier (`com.apple.voice.` or `com.apple.ttsbundle.`), and a successful `AVSpeechSynthesisVoice(identifier:)` lookup. On iOS 17+, Personal Voice is excluded without requesting its permission. There is no default/language-constructor fallback and no third-party synthesis provider. Identifier prefixes are a conservative application allowlist, not a promised stable Apple naming contract; unknown future identifiers are refused. The public iOS voice API exposes no Android-style network-required flag. Installed voice selection and exclusion of providers are source-verified; physical offline playback remains an acceptance requirement.

Each accepted iOS request has a fresh synthesizer and exact utterance identity. `usesApplicationAudioSession = false` lets the OS manage its separate playback session, mixing/ducking and active state. The module never activates/deactivates or reconfigures the app's shared recording session. Application inactivity/background and audio interruption begin cancel the active request; there is no resume.

**Android:** enumerate voices and require exact language/country, `!isNetworkConnectionRequired` and absence of `KEY_FEATURE_NOT_INSTALLED`; require `setVoice` success and read back the same voice name. No `setLanguage`, default voice or network fallback is used. Engine claims about local availability are the native API boundary; installed third-party engine behavior still requires offline device verification. The only manifest addition is TTS service package visibility, with no permission or background service.

Use speech content attributes and transient `MAY_DUCK` audio focus; API 26+ also uses `setWillPauseWhenDucked(true)` and refuses delayed focus. API 24–25 uses the legacy transient focus call. Denied focus refuses submission; every loss (including duck loss), background, or paused Activity cancels. Focus is abandoned after the native terminal callback. `QUEUE_FLUSH` is used defensively, but a busy run is always rejected rather than replaced or queued. App lifecycle and callbacks are serialized on the main looper.

Android lifecycle eligibility requires the Expo pause latch to be clear, a live non-finishing Activity, a non-destroyed module, and `ReactContext.lifecycleState == LifecycleState.RESUMED`. It does not require `Activity.hasWindowFocus()`: an in-app Dialog/React Native Modal can own focus while its Activity remains resumed. Expo SDK 55 exposes `appContext.reactContext` as `Context?`; a safe `ReactContext` cast makes missing or unexpected contexts fail closed. Installed RN 0.83.10 provides `ReactContext.getLifecycleState()` and the `LifecycleState` enum.

This eligibility check does not establish top-resumed position. Android 10+ can keep multiple activities resumed in multi-window mode, and system overlays may take window focus without pausing an Activity. The existing OS audio-focus request, denial, loss handling and Android 15+ top-app restriction remain authoritative and unchanged. Modal playback and multi-window behavior still require physical Android verification. See [Activity window focus and lifecycle](https://developer.android.com/reference/android/app/Activity#onWindowFocusChanged(boolean)).

An Android processing error requests stop rather than treating the error callback alone as proof that buffered audio stopped. Its `error` terminal is delivered after matching `onStop`/`onDone`; an engine that omits that acknowledgement remains quarantined. A throwing native submission is also uncertain: even `{accepted:false}` requires a confirmed `stop()` before releasing an acquired audio lease.

No utterance text is logged, written to a file, included in events, or sent by this code to an external service. No settings, downloads, new permissions, models, or new runtime packages are added. Android's `compileOnly 'com.facebook.react:react-android'` uses the host app's existing RN version; it adds no version pin or second packaged RN runtime. Text exists only in the native request needed for playback. The module accepts caller-provided text without changing its content or provenance.

## Verified API evidence

Accessed 2026-11-04. Compile evidence uses the installed Xcode iPhoneOS 27.0 SDK with target `arm64-apple-ios15.1`, and installed Android 36 `android.jar`. API compilation does not establish physical playback behavior.

| API / source | Minimum / relevant contract | Decision |
| --- | --- | --- |
| [Apple `usesApplicationAudioSession`](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/usesapplicationaudiosession) and installed `AVSpeechSynthesis.h` | iOS 13+; false uses a separate system-managed playback session | Set false; preserve app recording session |
| [Apple voice identifier lookup](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisvoice/init(identifier:)) and installed header | iOS 9+; unavailable/not downloaded identifier returns nil | Exact installed system voice only |
| [Apple `stopSpeaking(at:)`](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/stopspeaking(at:)) and installed header | Stop current speech and clear queue; Bool indicates call success | Await exact delegate terminal; never infer pre-start completion from Bool |
| [Android `Voice`](https://developer.android.com/reference/android/speech/tts/Voice) | API 21+ network requirement | Reject network voices |
| [Android engine constants](https://developer.android.com/reference/android/speech/tts/TextToSpeech.Engine) | API 21+ not-installed feature can trigger download/fallback | Reject not-installed voices; no default fallback |
| [Android `onStop`](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener#onStop(java.lang.String,boolean)) | API 23+ callback includes requests flushed before start | Await callback; deduplicate exact native token |
| [Android Activity window focus](https://developer.android.com/reference/android/app/Activity#onWindowFocusChanged(boolean)) and installed RN 0.83.10 `ReactContext.java` / `LifecycleState.kt` | Window focus and lifecycle are independent; multi-resume exists on API 29+ | Use resumed lifecycle eligibility, not Activity focus; do not claim top-resumed proof |
| [Android audio focus](https://developer.android.com/media/optimize/audio-focus) | API 26+ focus request; Android 15+ requires top app or foreground service | Foreground Activity only, no service; fail closed on denial |

Decision scope: use platform installed synthesis, no new dependency/OS requirement. A generic Expo speech wrapper's default-language fallback and queue are unsuitable for the required local-only, one-request contract. Missing local voice, unknown cancellation, and denied focus remain explicit refusals rather than fallback behavior.

## Verification and remaining acceptance

`sh modules/deck-speech/tests/run-tests.sh` (from `apps/mobile`) compiles and executes actual Swift identity-gate tests and actual Kotlin engine tests against deterministic fake OS ports. These cover busy refusal, network/not-installed rejection, failed voice selection, focus denial/loss, stop before start, delayed start, callback duplication, old-token isolation, stop timeout quarantine, native-confirmed disposal, and uncertain submission. A separate pure Kotlin foreground policy test permits a resumed Modal owner without window focus and refuses paused/background, non-resumed/unknown, finishing, destroyed or missing Activity/module states. These tests produce no speech. The foreground API and full Kotlin module sources were additionally compiled against the installed RN 0.83.10 AAR classes and Android 36 SDK, using private Expo DSL signature stubs; that is not an app Gradle build. Native engine files are also separately typechecked against actual platform SDKs; Expo glue needs the app's native build.
